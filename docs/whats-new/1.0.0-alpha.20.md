# 1.0.0-alpha.20

_Part of [What's new](../whats-new.md)._

- **Follow every live run at once.** `ork decide --follow` (or `--watch`) stays
  open and asks each open decision, then each new one, across your live runs,
  and `ork logs -f --all` interleaves their lines under a `<id> <workflow> ›`
  prefix; both pick up runs that start later, and `--until-idle` ends them when
  nothing is left. `ork logs <run>` now prints the runs it called inline under
  `call ›`; `--no-calls` turns that off, and `--json` includes them only with
  `--calls`
  ([decide](../guides/running-workflows/attaching-to-a-run.md#answering-for-several-runs-ork-decide---follow),
  [logs](../guides/running-workflows/looking-back.md#follow-every-live-run)).
- **Close several follow-ups at once.** `ork follow-ups done`, `drop`, `reopen`
  and `due` take several ids, by spaces or commas, and change none if one is
  unknown or can't take the action. Commands that take one id now refuse a
  second one instead of ignoring it
  ([guide](../guides/follow-ups.md#reading-and-closing-them)).
- **`ork once --on` keys a check by the files it reads.** `--on <pathspec>`
  (repeatable) hashes only the files the git pathspecs match, so an edit
  elsewhere still reuses the pass. A pathspec git refuses, pathspecs that match
  no file (most often a typo, which would otherwise pass for ever) and `--on`
  with no value stop before the command runs. Repeated `--covers` now records
  every name
  ([guide](../guides/running-workflows/several-runs.md#run-a-check-once-ork-once)).
- **A watched trigger's MCP server program is accepted too.** The hash behind
  `ork watch --accept` now covers a file in your project that an `mcp.call`
  check's stdio server runs (its `command` or an argument, also
  `--config=./x.json`), and a tool check's `--flag=./file` in its command or
  interpreter. Editing one turns the trigger off until you accept it again. Not
  covered: a program outside the project (`npx`, a global binary), a path built
  from an environment variable, and what a program itself reads. Upgrade: a
  trigger you accepted that names such a file turns off once; run
  `ork watch --accept` ([guide](../guides/watching.md),
  [limits](../../specs/scheduler/watching-limits.md)).
- **OpenCode refuses `ork` and `ork_*` server names.** A node on `open-code`
  that names an MCP server `ork` or `ork_<x>` fails before its session starts,
  naming the server, because OpenCode would call its tools `ork_<tool>` like
  Ork's own. Rename the server; `orkish` is fine
  ([guide](../guides/drivers.md)).
- **A first refused filter says nothing is filtered yet.** In `ork ui`, a filter
  refused before any has worked says "Nothing is filtered yet." rather than that
  the list shows the last filter that worked
  ([filtering lists](../guides/filtering-lists.md#in-the-browser-and-ork-mcp)).
- **Resolve feedback you fixed by hand.** `ork feedback resolve <item>…` marks
  items resolved (several ids, space or comma separated; none change if one
  can't be). `ork feedback list` and the Feedback panel now hide resolved items
  as well as dismissed ones (the panel's Status reads `Default (open)`), and a
  resolved item seen again opens as `new`
  ([guide](../guides/feedback.md#reading-it)).
